# 墨线框架 v2.1.0

墨线是一套面向单机、多智能体协作的规格驱动开发框架。它用中文文档定义流程、角色与验收标准，把变更 spec、测试与覆盖率要求写成可检查的条目，供产品、设计、架构、前端、后端与测试在同一个代码仓里分头推进需求。本仓是框架正文的独立仓，v2.0.0 于 2026-11-27 从主仓 simo 的 `docs/framework/` 整体迁入；主仓此后不再维护框架正文，只保留指向本仓的指针。

远端为 `git@github.com:YJM1024/moxian-framework.git`，页面为 <https://github.com/YJM1024/moxian-framework>，分支 `main`。

## 本仓是什么

本仓只放框架本身：规则册、任务矩阵、角色、档位、自检脚本、模板、域增量、适配层，以及 v2 的设计、调研、验收与回滚记录。它不绑定某一个产品或代码仓，接入方按自己的项目建立变更包与测试产物，再引用本仓的条文和验收标准。

版本号只写在根目录的 `VERSION` 一处，当前为 `v2.1.0`。条文里出现的 `docs/framework/…` 都从本仓根目录起算，克隆后可以直接按路径打开。

## 怎么用

第一次进入先读 `docs/framework/README.md`，它回答每个文件管什么、一次变更怎么走、脚本怎么用、出问题怎么回滚。之后按四步推进。

1. 判任务类型：读 `docs/framework/TASK-MATRIX.md`，定任务类型与执行要求；档位按 `docs/framework/EFFORT.md` 取。
2. 建变更包：在 `specs/changes/<CHG-ID>/` 下按角色写 spec，产品视角五份、技术视角三份；owner 按 `docs/framework/ROLES.md`。
3. 写验收标准：每个功能点的验收标准与端到端用例在开工前冻结，写不出可执行标准的不开工。
4. 测试与收口：跑全量单元、集成、端到端与真机关键路径，单元与集成覆盖率各不低于 95%；收口由项目经理写四节验收报告，产品写复盘。

已有项目迁到 v2.1 时先读 `docs/framework/ADOPTION.md`，它给出迁移步骤与回退方式。旧规则号到新规则位的映射在归档里，查历史引用用索引，不在正文恢复旧号。

框架不设门禁。`scripts/` 的五个工具只作自检，退出码非 0 由 owner 判断，不阻断发版。

## v2 与 v1.7.5 的关系

v2.0.0 是对 v1.7.5 的结构性重写，v2.1.0 在此基础上把角色与文书收敛为七角色自证、一份验收报告。规则册从十三章加附录改为九章加附录 A 至 D，现行 147 条，另有 20 条废止条保留原编号。

| 维度 | v1.7.5 | v2.1.0 |
|---|---|---|
| 章数 | 13 章加附录 | 9 章加附录 A 至 D |
| 条数 | 285 条 | 147 条现行，20 条废止条保留编号 |
| 规则编号 | 旧式章号加序号 | 三段式 `MXV2-<章>-<序号>` |
| 规则字段 | 判据与执行混写 | 六字段固定，验收标准与执行分开 |
| 角色 | 8 个 | 7 个，含项目经理，不含验收角色 |
| 状态 | 需求点五档与任务卡五状态并存 | 流程点五值：未开始、进行中、已完成、阻塞、已取消 |
| 门禁 | 名册与逐条判据混排 | 不设门禁，脚本只作自检 |
| 验收 | 验收角色签字 | owner 自证，项目经理汇总一份四节报告 |

处理细节写在 `docs/framework/v2/CHANGELOG.md`，迁移步骤写在 `docs/framework/ADOPTION.md`，v1.7.5 原文在 `docs/framework/archive/v1.7.5/`。

## 版本与变更记录

`VERSION` 是版本号的唯一出处，当前为 `v2.1.0`。根目录 `CHANGELOG.md` 汇总 v1.0 至 v2.0.0 的演进，`docs/framework/v2/CHANGELOG.md` 记录 v2 的结构性变更与差异摘要，两者不互相抄写条文。

## 已知边界

`examples/` 是 v1.7.3 时期随仓带入的存量件，按当时平铺的 `docs/` 布局读取文件，v2.1 正文不依赖它。`scripts/` 的五个自检脚本按本仓布局运行，不依赖接入仓。

`docs/framework/archive/` 下的两份历史快照与归档脚本只读，不参与 v2.1 的判定，内部链接按各自当时的布局解释。
