# 用户体验与视觉设计

从完整用户任务理解入口、信息架构、内容与术语、导航、关键路径和退出；覆盖初始、等待、空、无权、错误、重试、取消、完成及返回。决定层级、布局、密度、字体、色彩、反馈、响应式和设计系统一致性，同时考虑键盘、焦点、对比、重排、目标尺寸与辅助技术。

根据实际变化选用对应条目。现有工程能力足够时直接使用，复用代码栏给出重复缺口应归属的位置。

## 2.1 每个可达状态都给出用户能理解的反馈与下一步

用于保存设置、提交审批、上传中断、空列表。

- 工程入口　沿现有组件或原型走等待、失败、取消、重试路径。
- 可复用代码　多处需要相同反馈时复用组件库的状态与恢复组件。
- 专业判断　设计决定取消的实际含义、重试保留哪些输入。
- 验收　一次失败后用户能辨认结果并继续，同次提交不会因提示误导而重复发生。

采纳自NN/g「系统状态可见」「用户控制与自由」「识别、诊断并恢复错误」。[原文 1](https://www.nngroup.com/articles/ten-usability-heuristics/)

## 2.2 保持活动层可访问，按任务选择初始与返回焦点

用于确认删除、编辑弹窗、模态内出现验证错误。

- 工程入口　原生 dialog、真实浏览器键盘交互和无障碍树。
- 可复用代码　共享对话框缺这项行为时，在公共组件补一次。
- 专业判断　设计决定安全初始动作、触发控件消失时的合理返回位置。
- 验收　Tab 正反向、退出、返回及模态内错误可感知。项目要求读屏公告时在目标辅助技术上验证。

采纳自APG Modal Dialog 的键盘与焦点规则、HTML inert。[原文 1](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) [原文 2](https://html.spec.whatwg.org/multipage/interaction.html#inert-subtrees)

## 2.3 核对对比、重排、焦点和可操作尺寸及各条例外

用于主题、窄屏布局、密集工具栏、键盘路径修改。

- 工程入口　浏览器缩放、响应式视口、样式计算及已有无障碍检查。
- 可复用代码　跨页面的色彩或尺寸修正在现有设计令牌或公共组件实现。
- 专业判断　设计确认目标等级、支持范围及二维表格等例外是否成立。
- 验收　在所声明宽度与主题下，关键信息可读，焦点可见且可操作。证据对应实际验证的条款与页面。

采纳自WCAG 2.2 1.4.3/1.4.10、2.4.7/2.4.11、2.5.8 与第 5 章。[原文 1](https://www.w3.org/TR/WCAG22/)

## 2.4 沿用平台语义和项目视觉语言

用于新页面、主题切换、长译文或密集表单。

- 工程入口　现有设计系统、真实样例内容、浏览器或已有视觉对比。
- 可复用代码　重复使用的控件与排版规则归到组件或样式库。
- 专业判断　设计判断主次、术语、动效及品牌适配。
- 验收　主要操作容易辨认，长内容和错误提示仍可用。视觉差异经设计核对到具体影响。

采纳自Anthropic frontend-design 的层级、内容与响应式原则，Vercel Web Guidelines 的表单与文案建议。[原文 1](https://github.com/anthropics/skills/blob/e4bb5d960d87126ff3b3a8af1a104b7db67560ba/skills/frontend-design/SKILL.md) [原文 2](https://github.com/vercel-labs/agent-skills/blob/5a37a6329fbad3666c3207392a6a7c0110e92efb/skills/web-design-guidelines/references/command.md)
