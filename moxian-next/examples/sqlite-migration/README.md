# 工单优先级迁移

旧客户端按列名写入 id、title。新客户端增加 normal 与 urgent 两个优先级。历史缺失值和旧写入均表示 normal，已知 urgent 需要保留，遇到其他历史值应停在可恢复状态。数据库模型仅包含本例的表与列。

架构条目 3.3 和数据条目 6.2 决定分两步发布。先增加可空列，过渡版读取时将 NULL 解释为 normal。再在单个事务中复制历史记录、检查取值并收紧约束。旧版命名列写入在最终结构中取得默认值。项目调用方在第二阶段发生异常时回滚事务。故障修正后可从该阶段继续。

在本目录运行 `python3 -m unittest -v`。两个独立 SQLite 连接模拟同时存在的版本，覆盖既有数据、过渡期新旧写入、最终默认值、非法新写拒绝，以及遇到异常历史值后的回滚和修正后重试。测试数据位于临时目录。这个例子验证 SQLite 上的声明范围，其他驱动、触发器、外键、规模与上线锁窗口要在目标工程验证。
